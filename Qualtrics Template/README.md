# Qualtrics template: LLM-generated practice test with personalized feedback

`Tea_Survey_Part_2_Public.qsf` is an export of the Study 4 practice-test survey (Part 2 of the study), with the OpenAI API key removed. It is the survey described in the Tutorial section of the paper: ten short-answer questions (SAQs) about the TED-Ed video on the history of tea, each followed by personalized feedback generated by an LLM through a Qualtrics Web Service element, plus a restudy condition in which participants rewatch the video.

The file was exported on 11 September 2026 from a copy of the survey used for data collection. Two things differ from the live survey: the API key in the ten `Authorization` headers has been replaced by the placeholder `YOUR_OPENAI_API_KEY`, and unused questions from earlier builds have been removed from the survey's trash. Everything in the survey flow is as run.

## Importing the survey

1. In Qualtrics, go to **Projects**, then **Create a new project**, then **Survey**, then **Import a QSF file**, and choose `Tea_Survey_Part_2_Public.qsf`.
2. Open the imported survey and go to **Survey flow**. Each of the ten `Tea Q01 Sequence` to `Tea Q10 Sequence` groups contains a Web Service element. In each one, replace `YOUR_OPENAI_API_KEY` in the `Authorization` header with your own key (the header value is `Bearer <your key>`). The key must be entered in all ten elements.
3. Set a monthly spend limit on the OpenAI project that owns the key, and enforce it as a hard limit, so that a misconfigured survey cannot run up a bill.
4. Preview the survey and complete one SAQ sequence to confirm that feedback comes back before launching.

The survey is imported inactive. The Prolific ID question at the start, the end-of-survey redirect, and the anonymized-response setting are as used in Study 4 and can be changed under **Survey options**.

## How the survey works

- **Embedded data** (first element of the survey flow) holds the content: `Tea_Q01` to `Tea_Q10` (the questions), `Tea_MA01` to `Tea_MA10` (model answers), `Tea_R01` to `Tea_R10` (rationales), and `Tea_F01` to `Tea_F10` (feedback, empty until the Web Service fills it). `Group` records the condition.
- A **block randomizer** assigns each participant to the restudy block or to the SAQ group with equal probability.
- Inside the SAQ group, a second randomizer presents the ten question sequences in random order. Each sequence is a question block (a text-entry question piping `${e://Field/Tea_Q0n}`), a Web Service element, and a feedback block that displays `${e://Field/Tea_F0n}` and the model answer.
- Each **Web Service** element sends a POST request to `https://api.openai.com/v1/chat/completions` with four body parameters: `messages` (a system prompt with the audience level, a 0 to 10 scoring rubric and the evaluation approach, and a user prompt that pipes in the question, model answer, rationale and the participant's response), `model` (`gpt-5.4`), `reasoning_effort` (`medium`), and `max_completion_tokens` (2000). The response path `choices.0.message.content` is written to `Tea_F0n`.

## Adapting the survey to your own material

1. **Replace the content.** In the embedded data element, paste your own questions, model answers and rationales into `Tea_Q01` to `Tea_R10`. Leave the `Tea_F` fields empty. The field names can stay as they are whatever the topic; only the values change.
2. **Name the topic in the system prompt.** The first line of the system prompt in each Web Service reads "evaluating student responses about a video on the history of tea". Edit it in all ten elements to name your material. The rest of the prompt is topic-independent.
3. **Change the number of questions** by duplicating or deleting whole sequence groups in the survey flow. A new sequence needs its own question block piping `Tea_Q11`, a Web Service whose user prompt pipes `Tea_Q11`, `Tea_MA11`, `Tea_R11` and the new text-entry question, a response mapping to `Tea_F11`, and a feedback block displaying `Tea_F11` and `Tea_MA11`. Add the new fields to the embedded data element. The text-entry question is referenced by its Qualtrics question ID (for example `${q://QID265/ChoiceTextEntryValue}`), so after duplicating a block, check that the Web Service points at the new question's ID.
4. **Replace the restudy block** with whatever control activity your design needs, or delete it and the first randomizer.
5. **Change the model or provider** by editing the `model` value and, for a different provider, the URL, the header and the body parameters to that provider's chat-completions format. Some providers offer free tiers; check their terms on data use and rate limits before sending participant responses.

The full prompts used to generate the questions and the feedback are in the `Prompt & Questions` folders of Studies 3 and 4.
